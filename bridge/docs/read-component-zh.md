# 只读文件服务组件化

2026-09-14，CoNest 0.6.3 开发增量，接续[搜索服务组件化](search-component-zh.md)。`dsh_read` 现在由独立的 `dsh-read@0.1.0` 内建组件提供，两种 Loop 通过同一组件 worker 调用。既有发行包未替换。

## 本次迁移

| 范围 | 实现 |
|---|---|
| 文本读取 | `dsh-read` 组件装配原生 DSH ToolRuntime、LocalFileSystem 和 `read` 工具，暴露 `dsh_read` 能力 |
| Gateway 文件工具 | 保留 `write/edit/read_image`，不再注册本地 `read`，不设置读取回退 |
| 工具契约 | 保留 `file_path/offset/limit`、DSH 文本包络、行号、分页、结构化值与错误文案 |
| 组件管理 | 可单独停用、启用与授权；停用读取组件不影响搜索组件 |
| 读后写保护 | Gateway 接收 worker 的实际观察记录，保留原有版本校验和会话隔离 |

原生 `ToolFs` 一次注册多种文件工具，当前公开的包入口没有独立读取装配开关。本次通过子 Context 的工具注册视图选择 `read` 或其余工具，复用原生包的参数校验与执行逻辑；不修改共享 ToolRuntime、不复制读取算法、不修改冻结的上游源码。Gateway bundle 仍包含原生文件工具包，为写入、编辑及图片读取服务；文本 `read` 的注册与执行归 worker 所有。

Connector 核心工具增加为七个。`dsh_read` 无需 Studio 即可读取授权工作区；只有启用 Studio 后，读取观察记录才交接给其文件修改策略。两个 Loop 的工具都继续受宿主最终准入、运行生命周期、worker 能力策略及 `workspace:read` 权限约束。直接入口被拒绝时，不能通过 `bridge_invoke` 调用同名能力绕过。

## 读取行为与路径

相对路径以 Runtime 的工作区为基准；绝对路径、符号链接解析后的目标及不存在文件的最近现存祖先均须位于该工作区。原有 Studio 搜索/读取允许显式访问工作区外路径，本次读取入口收紧到已声明的工作区权限范围。返回的文件路径使用解析后目标的绝对路径，工作区内符号链接显示其实际目标。该路径检查仍属于受信代码中的边界检查，不是恶意组件或并发文件系统替换的内核沙箱。

保留原生默认值：每次最多 2,000 行、每行最多 2,000 字符、选中正文最多 50 KiB；文件达到 10 MiB 时使用流式读取。结果仍含总行数，超出文件末尾的 offset 按原生行为返回错误；非正整数、目录、非文本文件和缺失文件也沿用原生校验。取消信号传入真实 DSH 文件读操作及流式读取。

worker 的读取能力返回原生结果包络，包括 `content/value/isError`，读取失败时含 `error`；涉及文件观察时另带受信记录。能力成功返回该包络表示读取操作已产生结果，`isError` 决定文件操作是否成功。Connector 在直接和通用工具入口将读取错误转换为宿主工具失败，并从返回模型的数据中剥离内部观察记录。

## 为什么需要交接读取记录

DSH 的 `fs-observation-policy` 按会话和文件身份记录实际观察到的版本。原生 `edit` 要求先读取，原生 `write` 对已读文件按版本替换；修改动作在 Gateway 的原生文件系统内再次校验版本。如果只迁走读取而不交接这条记录，正常的读后编辑会被误拒绝。

worker 使用每次调用独立的 AsyncLocalStorage 捕获原生 `fs/observed` 事件。成功读取记录文件身份及该次读取使用的版本；确认文件不存在时记录缺失状态。不同调用即使复用 toolCallId 也不共享观察容器。

Connector 仅从受信 worker 的实际调用返回接收记录，通过内部回调交给对应 Studio 工具会话。Gateway 校验目标仍在工作区、身份未改变且调用未取消，然后把原记录交给现有策略。该接口不读取模型参数中的版本，不从文本推断观察结果，也不重新读取文件或采纳较新的 stat 版本。

因此：未读文件仍不能直接编辑；另一会话不能借用本会话的读取记录；文件被外部修改后，即使读取记录稍晚才到达 Gateway，也仍使用旧版本并拒绝覆盖。确认缺失的记录可使后续写入继续走安全的 `createIfAbsent`。写入、编辑的审批与执行仍由原生 Gateway 工具负责，本次没有将它们迁入 worker。
